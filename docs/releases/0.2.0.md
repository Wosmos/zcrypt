# zcrypt 0.2.0

Released 2026-11-01. Previous release: 0.1.7 (2026-10-04). The planned 0.1.8 was folded into this release.

## Highlights

- **Eight languages, all the way through.** The app, the website, every docs page and the privacy and terms pages in English, Arabic, German, Spanish, French, Russian, Urdu and Chinese, with right-to-left layouts for Arabic and Urdu.
- **You always know what is happening.** System notifications on the web, desktop and Android; optional sounds; a new transfers panel; progress in plain words that never goes backwards; failures that say how to fix them.
- **Undo instead of "are you sure?"** Deletes and moves happen straight away with an Undo bar. Confirmations are kept for permanent actions, and they say how many items are affected and show which ones.
- **A calmer, faster vault.** Recents and Starred, one search in the top bar, right-click menus, loading skeletons, and big vaults that no longer flicker or blank the page.
- **Privacy work underneath.** Space names and the Send hash are sealed on your device, the app never sends a file name or hash in the clear, the CSP is enforced, sharing keys are pinned, and session IPs are shortened.
- **New pages.** Public `/feedback`, a changelog with a page per version and an RSS feed, and an in-app What's new dialog.

The full list is in [CHANGELOG.md](../../CHANGELOG.md#020---2026-11-01) and at <https://zcrypt.cloud/changelog/0.2.0>.

## Breaking changes and how to migrate

1. **Plaintext file names are refused.** `POST /api/upload/init` without a sealed `encrypted_name` now returns HTTP 426 with `{"code":"client_update_required"}`.
   - Users: update the desktop or Android app if it asks. Every 0.1.6 or newer app already seals names.
   - Custom clients: send `encrypted_name` (the `enc1:` sealed form described in [`docs/CRYPTO_FORMAT.md`](../CRYPTO_FORMAT.md)) and leave `filename` empty.
2. **Client IP header on Railway.** The server now trusts `X-Real-IP` when `RAILWAY_ENVIRONMENT_NAME` is set. Behind another proxy, set `ZCRYPT_CLIENT_IP_HEADER` to the header your proxy sets, or `none` to keep the old `X-Forwarded-For` hop counting (`ZCRYPT_TRUSTED_PROXY_COUNT`).

## Upgrade steps

**Web:** nothing to do. Reload the page once.

**Desktop:** the built-in updater offers 0.2.0. Apps from v0.1.4 and older can't self-update; reinstall with the one-liner from the README.

**Android:** download the new APK from the releases page and install it over the old one. Copies installed before v0.1.7 were signed with a different key: uninstall once, then install.

**Self-hosted backend:**

1. Pull `main` at `v0.2.0` and rebuild the image (`docker build -t zcrypt .`). The Dockerfile now downloads the monthly DB-IP Lite city database into `/geo/dbip-city-lite.mmdb`. The build needs outbound HTTPS to `download.db-ip.com`.
2. Optional new environment variables: `ZCRYPT_CLIENT_IP_HEADER`, `ZCRYPT_GEOIP_DB`. Without the database file, location lookups are skipped and everything else works.
3. Restart. Schema migrations run on start, and no manual SQL is needed.
4. Check `GET /api/health` returns `{"status":"ok"}`.

## Known issues

- **macOS installers are not notarized** and Windows installers are not signed yet. Use the one-line installers or follow the "Open Anyway" steps in the README.
- **iPhone:** the web app can't keep transferring in the background. Keep the tab open, or use a computer or Android phone for large transfers.
- **glib advisory (medium)** in the Linux desktop build is accepted for now: Tauri pins glib 0.18 and no Tauri release has moved off it.
- **Load capacity is unmeasured.** The k6 scripts exist, but no run has been recorded, and the upload scenario still needs updating for sealed names.
- **HuggingFace** limits commits to about 128 per hour per repo, so a very large bulk delete there finishes over several minutes.
- **Account master key (mk1)** support ships switched off, behind an admin rollout switch.
